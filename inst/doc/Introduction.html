Using optimTFE

The optimTFE package is a spatial conservation prioritization (SCP) tool created to help conservation managers identify priority recovery areas, represented by planning units, for species recovery planning efforts.

This vignette will demonstrate how to bring in data for use in the optimTFE algorithm to generate conservation solutions, which we refer to as conservation footprints. It will then provide examples of how to generate relevant summary statistics in order to explore conservation footprints and tradeoffs.

Project Setup

The optimTFE package includes an example dataset that we will use for the following examples. First, we will load the package and define our project directory. For demonstration purposes, we will create an ephemeral temporary directory, projectDir. In a real project you would use the root of your project directory and optimTFE will use the current working directory by default if not specified. The run_id (default = “optimTFE”) will be used as a subdirectory to store outputs for the current optimTFE run, allowing multiple runs to be organized within a single project.

library(optimTFE)
library(dplyr)
library(ggplot2)
projectDir <- tempdir()
run_id <- "optimTFE"

Minimally, optimTFE must be provided with 2 required inputs. The first input specifies the required targets for each species (i.e., the number of desired planning units per species). It can be provided as a file path to a csv, where the first column contains the species names and the second column specifies the total species-specific targets (note: species names must not contain spaces or special characters). Alternatively, the species targets can be provided as a pre-loaded R data.frame or matrix, with the species names set as the row names, not in a separate column. The optimTFE package includes an example data set of 30 species and an example targets data frame (with total targets in the first column) that can be used for testing.

The species suitability can be provided as a file path to a csv with species names in the first column or a preloaded R data.frame or matrix with species names set as row names. The species names provided in the suitability matrix must match those provided in the targets input. Values in the suitability matrix should fall between 0 and 1 (inclusive) and binary values can be used when data on relative suitability across units are not available. Running optimTFE

We can then run the minimal example, which will generate output files prefixed with the run_id in the specified directory, out_dir.

optimTFE(
  targets = example_targets[, 1, drop = FALSE],
  suitability = example_suitability,
  min_spp_suit_score = 0.2, # Set suitability scores lower than 0.2 to 0
  rand_tolerance = 10, # Range of species richness to consider at each step
  n = 5000, # number of solutions to generate
  out_dir = projectDir,
  run_id = run_id,
  output_csv = TRUE,
  cores = 4, # number of processing threads to use
  seed = 101010 # Seed for reproducible output
)

Input Validation

The optimTFE algorithm will attempt to validate all inputs to ensure that inputs are in the proper format, that the species names and planning unit ids are consistent across inputs, and that the requested targets can be met. A dry_run parameter is available to validate inputs without running the algorithm:

impossible_targets <- example_targets[, 1, drop = FALSE]
impossible_targets[1:5, 1] <- 1000
optimTFE(
  targets = impossible_targets,
  suitability = example_suitability,
  dry_run = TRUE
)

Progress Updates

When generating a large number of solutions it can be helpful to have an indicator bar showing progress of the algorithm. optimTFE uses the package {progressr} to provide progress notification. You can activate progress bars for optimTFE by either turnning on the global progress handler once at the beginning of your R session:

progressr::handlers(global = TRUE)

Or you can explicitly wrap your individual function calls:

progressr::with_progress({
  optimTFE(...)
})

Either method will display a progress bar for long running calls to optimTFE. However, because optimTFE batches solution generation for efficiency, progress updated will occur at the batch level. As a result, if the number of batches in not significantly greater than the number of processing cores in use, updated will be minimal.

Optional Inputs

Known Populations

When there are known populations that should be prioritized for conservation targets, an additional populations input can be provided. Known populations can be provided as a file path to a csv in one of 2 formats. The file should either be in long-format, with 3 columns, unit_id, species, and population, or wide format, with columns for each species and one row per unit_id (with unit_id in the first column). Alternatively, the populations input can be provided directly as a wide format R matrix with unit_ids for row names and species names as column names. In the example populations data, viewing the first 10 planning units for the first 10 species shows single known population, “F”, in unit_5 for sp_5:

When provided to the optimTFE algorithm, species populations will always be preferentially selected and populations with suitability scores below the threshold (min_spp_suitability) will not be excluded.

Subregions

When explicit minimum numbers of targets are required within one or more subregions of the larger conservation area, subregion inputs can be provided. The subregion input should consist of a path to a csv with unit_id in the first column and a binary indicator in the remaining columns showing which region each planning unit occurs in. Alternatively, an R data.frame or matrix with unit_ids assigned to the row names can be provided. Planning units not assigned to a region will be assigned to a ‘default’ region at run time. For the first 10 planning units of the example data, units 1:7 will be placed in the default region, while units 8:10 occur in the ‘left’ region:

Species Incompatibilities

When species with overlapping ranges must not be assigned to the same conservation planning units (e.g., due to the potential for undesired hybridization), a species incompatibility matrix can be provided. This input does not need to include all species (only those with incompatibilities) but must be a symmetric binary matrix with species names defining rows and columns with 1 indicating an incompatibility. Here we can see the incompatibilities between a few of the first 10 species in the example data:

Exploring Results

By default, the complete details of all solutions will be saved as a collection of .parquet files in the solutions subdirectory, but can also be saved as a single csv file with the output_csv = T option. However, generating a very large number of solutions can result in large file sizes and it will most often be more efficient to query the parquet files using the {arrow} package, which provide efficient data filtering and loading without requiring the entire output to be read into memory. The optimTFE package includes some helper function to simplify this process. For, example, the get_solutions() function can be used to import one or more solutions from the output. For example, to extract the first 10 solutions:

sols_1_to_10 <- extract_solutions(
  solutions = 1:10,
  dir = projectDir,
  run_id = run_id
)

The summary data can be use to find the range of footprint size across all solutions and extract a subset. In this case, will will plot the distribution of the number of units selected per footprint:

sol_summary |>
  dplyr::summarise(
    Frequency = dplyr::n(),
    .by = n_units
  ) |>
  ggplot(aes(x = n_units, y = Frequency)) +
  geom_bar(stat = "identity", fill = "steelblue") +
  theme(
    panel.background = element_blank(),
    plot.title = element_text(hjust = 0.5),
    axis.text.x = element_text(angle = 45, hjust = 1)
  ) +
  labs(
    title = "Planning unit counts across all solutions",
    x = "Planning unit count",
    y = "Frequency"
  )

Then we can use the helper function, extract_solutions() to extract the solution data for the smallest 10% for footprints base on the n_units summary attribute:

min_10_pct <- quantile(sol_summary$n_units, probs = 0.1)

  solutions = which(sol_summary$n_units <= min_10_pct),
  dir = projectDir,
  run_id = run_id
)

Spatial Data

Spatial data can be added to the solution summary output using the function spatial_stats(). The spatial input to this function should be a path to an ESRI .shp file or .gpkg or a preloaded spatial data frame. In each case, the unique planning unit ids must be included in the first column of the attribute table. The function will return the input summary data frame with 3 new columns: area, perrimeter, and their ratio (pa_ratio).

sol_summary_spatial <- spatial_stats(
  data = sol_summary,
  spatial = example_spatial
)

Spatial data can also be used to generate a map of a given solution. In this example we generate a map of one of the footprints in subset with smallest total area and lowest perrimeter to area ratio, showing the species richness for each selected unit:

# Find a minimal solution
min_solution <- sol_summary_spatial |>
  filter(area <= quantile(area, probs = 0.05)) |>
  arrange(pa_ratio) |>
  slice(1) |>
  pull(solution) |>
  extract_solutions(
    solutions = _,
    dir = projectDir,
    run_id = run_id
  )

# Join with spatial data and plot
left_join(
  example_spatial,
  min_solution,
  by = "unit_id"
) |>
  ggplot(aes(fill = richness)) +
  geom_sf(color = "grey") +
  scale_fill_viridis_c(
    direction = -1,
    na.value = "white",
    name = "Richness"
  ) +
  theme_void() +
  labs(title = "Minimal Footprint") +
  theme(plot.title = element_text(hjust = 0.5))

Or, to create a map of planning unit selection frequency across all solutions:

# Calculate unit frequency
unit_frequency <- extract_solutions(
  dir = projectDir,
  run_id = run_id,
  columns = c("solution", "unit_id")
) |>
  summarise(
    Frequency = n() / 1000, # n = 1000
    .by = "unit_id"
  )
# Join with spatial data and plot
left_join(
  example_spatial,
  unit_frequency,
  by = "unit_id"
) |>
  ggplot(aes(fill = Frequency)) +
  geom_sf(color = "grey") +
  scale_fill_viridis_c(
    direction = -1,
    na.value = "white",
    name = "Frequency"
  ) +
  theme_void() +
  labs(title = "Frequency of planning unit selection") +
  theme(plot.title = element_text(hjust = 0.5))
